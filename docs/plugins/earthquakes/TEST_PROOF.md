## Tool

| tool | params (the adapter's own `ALLOWED_PARAMS` + `mode`, in the adapter's order — anything else is 400 `unknown_param`) | cacheSeconds |
|---|---|---|
| `earthquake_search` | `starttime`, `endtime` (string, `YYYY-MM-DD` or `YYYY-MM-DDTHH:MM:SS(Z)` UTC), `minmagnitude`, `maxmagnitude` (number -2..10), `latitude` (-90..90), `longitude` (-180..180), `maxradiuskm` (0..20001.6 — circle needs all three), `minlatitude`, `maxlatitude` (-90..90), `minlongitude`, `maxlongitude` (-180..180), `limit` (integer ≥ 1, default 100, adapter caps at 200), `orderby` (enum time\|time-asc\|magnitude\|magnitude-asc, default time), `mode` (enum query\|count, default query) | 60 |

The handler runs `/api/sources/earthquakes?<same query>` in-process (`createPluginInvoker` over `sourceMounts()` → `earthquakes-route.js` → `usgs-earthquakes.js`), passes the adapter's `data` (`source, coverage, count, events, query` + `mode`) and `provenance` through unchanged, adds `provider: { status:'live', source:'USGS FDSN Event Web Service', … }`, and maps failures 1:1 — same HTTP status, same code: `invalid_query` (400, or `unknown_param` when the adapter names unknown keys), `usgs_rejected` (400/404), `usgs_unavailable` (502/5xx), `usgs_timeout` (504), `sources_error` (502). The whitelist is derived from the exported `ALLOWED_PARAMS` at import time, so it cannot drift from the Gate 3 adapter (asserted by the tests).
