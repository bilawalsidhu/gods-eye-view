# TEST PROOF — `vessels` plugin (OnDemand Spatial Live Vessels, AIS)

Recorded 2026-09-18T16:33:22Z (UTC). Module `server/tools/vessels.js`; routes served by `server/serverless/tools-route.js` from the existing catch-all function; OpenAPI generated by `scripts/generate-tool-openapi.mjs` into `docs/plugins/vessels/openapi.json` (not hand-edited).

## Tools

| tool | params (validateParams whitelist — anything else is 400 `unknown_param`) | cacheSeconds |
|---|---|---|
| `vessels_in_bbox` | `lat` (number, required, -90..90), `lon` (number, required, -180..180), `lamin`/`lomin`/`lamax`/`lomax` (numbers, optional — all four define the box, a partial set is 400), `radiusKm` (number, default 60, 5..300), `limit` (integer, default 200, 1..2000), `maxRows` (integer, default 2000, 1..12000) | 20 |
| `vessel_by_mmsi` | `mmsi` (string, required, `^\d{5,10}$`), `lat`/`lon` (numbers, optional, together — default box = Texas Gulf coast demo area 28.85..29.85 / -95.35..-94.00), `radiusKm` (number, default 150, 5..300) | 20 |

Both run `/api/ais-live` (bounded collector: ≤ 8 s AISStream window per scene box, 25 s snapshot cache) in-process via `server/tools/_invoke.js`; `vessel_by_mmsi` adds `/api/ais-live/track?mmsi=`. Rows are normalised to `{ mmsi, name, imo, type, destination, lat, lon, speedKt, courseDeg, headingDeg, lastPositionUtc, distanceKm }` and sorted nearest-first. Without `AISSTREAM_API_KEY` the answer is the labelled demo replay (`status: degraded`, source `Demo replay`); a box outside it is `ok:true`, `count 0`, `status: empty` + `statusMessage`; a route 503 (rejected key / failed collection / AISHub refusal) is `ok:false` with the route's `provider`; an unknown MMSI is 404 `not_found`.
