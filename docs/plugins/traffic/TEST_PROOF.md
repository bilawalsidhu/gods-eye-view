# TEST PROOF — `traffic` plugin (OnDemand Spatial Street Traffic, TomTom Flow Segment Data)

Recorded 2026-09-18T16:33:22Z (UTC). Module `server/tools/traffic.js`; routes served by `server/serverless/tools-route.js` from the existing catch-all function; OpenAPI generated by `scripts/generate-tool-openapi.mjs` into `docs/plugins/traffic/openapi.json` (not hand-edited).

## Tools

| tool | params (validateParams whitelist — anything else is 400 `unknown_param`) | cacheSeconds |
|---|---|---|
| `traffic_flow_at_point` | `lat` (number, required, -90..90), `lon` (number, required, -180..180), `zoom` (integer, default 10, 0..22), `unit` (enum `KMPH`\|`MPH`, default `KMPH`) | 60 |
| `road_network_status` | none | 300 |

`traffic_flow_at_point` runs `/api/tomtom/flow-segment?point=lat,lon&zoom=&unit=` in-process (60 s per-point cache, daily request budget, last-good → `stale`). 200 → `data: { point, currentSpeed, freeFlowSpeed, currentTravelTime, freeFlowTravelTime, confidence, roadClosure, frc, coordinatesCount, unit, roadNetwork, zoom, stale, cache, fetchedAt }`. Keyless → **503** `{ ok:false, error:{ code:'not_configured', message:'TOMTOM_API_KEY not set — set it in Vercel to enable live traffic' }, provider }` (a DEGRADED reason, never 502). Other failures keep the route's HTTP status with a stable code (`upstream_auth`, `rate_limited`, `upstream_timeout`, `budget_exhausted`, `no_road_segment` (400), `malformed_upstream`, `upstream_unavailable`).

`road_network_status` returns `roadNetworkConfig()` from `server/providers/overpass/constants.js`: `{ source: 'overpass'|'off' (ROAD_NETWORK_SOURCE, default overpass), upstreams: string[] (OVERPASS_UPSTREAMS csv override, else the unchanged default mirror list), blocker: <fixed text>, fromEnv: { ROAD_NETWORK_SOURCE: bool, OVERPASS_UPSTREAMS: bool } }` plus `tomtom: { configured, provider }` from `/api/tomtom/status`. Env values are never echoed — only whether each variable is set and the parsed mirror URLs.

Austin at 17:31:20Z read the same text (plus a `· SIMULATE…` loading suffix). **Caveat observed in Austin:** in five earlier runs (samples at 17:09:38Z, 17:14:06Z, 17:21:46Z, 17:23:22Z, 17:24:46Z) the row read `UNAVAILABLE · OpenStreetMap · OpenStreetMap roads unavailable — public Overpass mirrors refuse this deployment (HTTP 406); simulated traffic needs O…` for ~4 s before returning to `DEGRADED · TomTom · …` — the OSM road fetch behind the simulated flow goes through `/api/overpass`, which the public mirrors answer with HTTP 406 from Vercel egress (the same blocker `road_network_status` reports). So the traffic row is DEGRADED most of the time but flaps to UNAVAILABLE around each failed Overpass attempt; it never showed `HTTP 502`.
