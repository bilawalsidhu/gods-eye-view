# Satellites plugin — test proof

- Plugin id: `satellites` — **OnDemand Spatial Satellites (CelesTrak)** (category Research)
- Module: `server/tools/satellites.js` (reuses `server/providers/space/celestrak.js` in-process via `server/tools/_invoke.js`; SGP4 from `satellite.js`)
- Recorded: **2026-09-18T16:34:10Z** (UTC)

## Tools

| Tool | Params | cacheSeconds |
| --- | --- | --- |
| `list_satellites_in_scene` | `lat`\* (−90..90), `lon`\* (−180..180), `radiusKm` (50..6000, default 1500), `groups` (csv of stations, visual, gps-ops, glo-ops, galileo, geo, starlink; default `stations,visual,gps-ops,glo-ops,galileo,geo`), `minElevationDeg` (−90..90, default −90), `limit` (1..500, default 50) | 60 |
| `satellite_passes` | `lat`\*, `lon`\*, exactly one of `noradId` (integer) / `name` (case-insensitive substring; aliases iss, tiangong, hubble…), `group` (enum, default `stations`, searched first), `hours` (1..72, default 24), `minElevationDeg` (0..90, default 10), `stepSec` (10..120, default 30) | 300 |

Every answer is `{ ok:true, data, provider, provenance }` or `{ ok:false, status, error:{code,message}, provider? }`; `provider` is the worst CelesTrak proxy status across the fetched groups (live / stale / degraded / unavailable), `provenance.groups` lists per-group status, `x-tle-source` (celestrak.org | celestrak.com | cache | snapshot) and `x-tle-cache`. Unknown / invalid query parameters are a 400 from the shared `validateParams`. Satellites are deduplicated by NORAD id (first group wins).

Covered (network fully mocked with `t.mock.method(globalThis, 'fetch', …)`, disk cache isolated, bundled snapshot disabled): TLE parsing / epoch decoding / haversine / SGP4 observation; `mergeProviders` worst-status rules; happy path through the **real CelesTrak proxy** with an ISS + CSS fixture (the ISS is found over its own sub-satellite point at elevation > 89°, cache HIT on the second call); ISS passes over London within 24 h with rise < max < set, an in-progress pass flag, alias and substring name lookup; 404 `not_found` after searching all seven groups; 400 for zero / two identifiers; stale + failed-group → `degraded`; every group failing → structured 503 `upstream_unavailable` (handler and HTTP envelope); 400 `unknown_param` / `invalid_param` / `missing_param` through `createToolsHandler({ index: toolIndex() })` with fetch forbidden; and `JSON.stringify(result)` never contains the fake `ONDEMAND_API_KEY` set for the test process.
