## Findings

1. **Visual observation happens in the Media API, not in the chat query.** The image agent (`plugin-1713958591`) analysed the PNG at upload time and returned its description in `data.context` — a correct, detailed reading of the chart (dark theme, lon/lat scatter, title text, magnitude legend). That `context` is the `visual_observation`.
2. **The chat query did not see the image**, with or without the image agent in `pluginIds`, on both sync and stream: the model answered that no image was available. Nothing in docs/ONDEMAND_API_CURRENT.md documents automatic injection of session media into a query; the documented path for making media answerable is the knowledge-ingest agent `plugin-1716472791` with `pluginInputs.postProcess.chatPluginId` (§5), which was not exercised (it creates account-side knowledge state).
3. **Provenance labelling for the OnDemandEvent/provenance envelope:** `{ kind: 'visual_observation', source: 'ondemand.media', mediaId, plugin: 'plugin-1713958591', observed_at_utc, text: data.context }` for what the model saw in pixels, versus `{ kind: 'structured_data', source: 'USGS FDSN Event', route: '/api/sources/earthquakes', retrieved_at_utc, events[] }` for adapter/tool results. When an answer must cover both, inject the media `context` string into the query text explicitly and keep the two kinds separate in the citations; never present a visual reading as observed data.
