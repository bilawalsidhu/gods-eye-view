### I.3 Recommendation — the open Overpass decision (and the other three upstreams)

**Overpass (Street Traffic road geometry).** Measured 2026-09-19T07:0xZ from this workspace: `overpass-api.de`, `lz4.` and `z.` answer **HTTP 406** to every request whose User-Agent contains `gods-eye-view` (the upstream project's identifier that PROVIDER_USER_AGENT still carries) or `example.com`, while neutral UAs get 200/504 — i.e. a UA-keyed refusal, not a query problem; `overpass.kumi.systems` answered 200 in 9.7 s once and timed out (>25–30 s) twice; `private.coffee` timed out. Community evidence: the public main instance has been unreliable through 2026, private.coffee mirrors carried stale `timestamp_osm_base` values (2026-01-15 / 2026-01-06), and there is an April-2026 discussion (pnorman) of requiring OSM sign-in / API keys for the public instance — https://community.openstreetmap.org/t/overpass-api-performance-issues/140598 , https://community.openstreetmap.org/t/overpass-api-performance-issues/140598?page=4 , https://community.openstreetmap.org/t/overpass-api-performance-issues/140598?page=8 . Alternatives on the table: the paid Geofabrik Overpass service, scope-limited instances, self-hosting (the MMD fork is faster with meta), FairwayMapper pooled slots (require 20 OSM changesets in 90 days), and server-side caching of bbox queries (schrankmonster measured ~28 s for an uncached bbox query — https://www.schrankmonster.de/2025/10/29/openstreetmap-overpass-but-cached/ ). **Recommendation:** a cached proxy in front of Overpass (edge `s-maxage` + the repo's 24 h memory / 7 d disk tiers already exist for local runs — a KV-backed tier is the serverless equivalent), an explicit per-mirror timeout (`OVERPASS_MIRROR_TIMEOUT_MS`, default 12 s) and a fallback mirror list (`OVERPASS_ENDPOINTS`), with self-hosting or Geofabrik as the paid option when the layer is load-bearing; whether to change the User-Agent identity that overpass-api.de refuses is part of the same decision. **Status: decision pending human** (the code already reads `OVERPASS_ENDPOINTS` / `ROAD_NETWORK_SOURCE=off`).

**OpenSky (Live Flights).** REST root `https://opensky-network.org/api`, `GET /states/all` with `lamin/lomin/lamax/lomax`; anonymous calls are rate-limited and authenticated access now uses OAuth2 client-credentials tokens — https://openskynetwork.github.io/opensky-api/rest.html . The proxy already requests OAuth (`x-opensky-auth-mode-requested: oauth`) and falls back to adsb.lol; the `HTTP 502 · retry 20s` seen on the pre-fix build was the raw upstream failure surfaced before the 2026-09-18 breaker/fallback landed. **AISStream (Live Vessels).** WebSocket `wss://stream.aisstream.io/v0/stream` with `APIKey` + `BoundingBoxes`; open issue #15 (Mar 2026) reports subscriptions accepted with zero messages delivered — https://github.com/aisstream/aisstream/issues/15 , https://dev.to/jj/follow-that-ship-with-aisstreamer-21g3 .
