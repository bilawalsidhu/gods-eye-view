## Normalization status

The branch's proxy (`api/ondemand/chat.js` + `server/ondemand/sse.js`) is a **verbatim pass-through by design** (docs/ONDEMAND_PROXY_DESIGN.md): upstream `event:`/`data:` lines, the `heartbeat`/`message` event names, the `eventType` payloads (`statusLog`, `metricsLog`, `fulfillment`, and the undocumented `fulfillment_thinking` seen on Claude endpoints) and the `[DONE]`/`[ERROR]:` markers reach the browser unchanged — there is no separate `OnDemandEvent` re-encoding layer in this branch, so there was no normalization bug to fix; the SSE unit tests (`server/ondemand/sse.test.mjs`) already cover verbatim piping of `[DONE]`/`[ERROR]:`. Recommended client contract (documented here for the UI work): treat `event:heartbeat` as keep-alive, reassemble `fulfillment` deltas by `eventIndex`, read `metricsLog.publicMetrics` for tokens/timings, surface `fulfillment_thinking` separately from the answer, and stop on `[DONE]` / raise on `[ERROR]:`.
