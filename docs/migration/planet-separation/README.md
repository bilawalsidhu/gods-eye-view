# План отделения слоёв и интерфейса от планеты

[Итоговая приёмка всех 33 слоёв и переключения движков](acceptance.md) содержит проверенную матрицу и команды воспроизведения.

**Решение.** Сохранить рабочую ветку и оба движка. Начать заново проектирование владения состоянием. Переписывать приложение или переключать все слои за один релиз не требуется. Пользователь выбирает планету; история, выбор рейса, эфир радио, открытая кабина и работа инструментов принадлежат сессии GEV. Внешний вид неба и технология отрисовки могут различаться. Это план работ, а не заявление о достигнутом паритете.

Основа инвентаризации — дерево Git `9824bbba0a8f6c8ab6dc7ebd3768ca0cbc4721a1` в `codex/navara`. Документ расширяет [предыдущую схему](../renderer-isolation.md). В ней реализован только первый шаг с `suspend()/resume()`. В `src/main.js` переключатель по-прежнему вызывает `application.destroy()`. На этой базе зарегистрированы 33 слоя, из которых 15 имеют фабрики Navara. Наличие фабрики показывает точку входа, а не полноту возможностей.

## Как пользоваться планом

- [Первые коммиты и условия выбора стратегии](execution.md) дают последовательность изменений с привязкой к файлам. [Контракты и подключение третьего движка](contracts.md) задают семантику операций и ошибок.
- [Матрица всех слоёв](layers.md) задаёт отдельный результат и проверку для каждого ID. [Работы по системам](systems.md) охватывают инструменты и владельцев вне каталога слоёв.
- [Реестр файлов](files.tsv) маршрутизирует каждый отслеживаемый путь исходного коммита в конкретный пакет работ. [Реестр интерфейсов](interfaces.tsv) охватывает публичные exports, пакеты из проверки границ, команды голоса и инструменты Core. [Реестр прежних сценариев](parity.tsv) сохраняет все строки четырёх старых матриц как обязательства по проверке. Старые оценки Dioxus и списки возможностей не используются как описание текущего состояния.
- Строка реестра означает «проверить и выполнить указанную операцию»; она не означает, что файл нужно переписать. Для ассетов, договоров провайдеров, документации, серверных кодов ошибок и уже чистой математики нормальный результат — доказать совместимость без изменений. Генерируемые сборки, установленные зависимости, временные артефакты и реальные локальные секреты не являются входами перечня.
- Перед каждой волной сверять новые пути, слои и exports с базой по `git diff --name-status 9824bbba..HEAD`. Новую функцию включать до закрытия волны. Для каждого пункта вести исходный пример, реализацию/коммит, результаты «без сцены / Cesium / Navara», наблюдаемое ограничение, измерение или ссылку на тест. Удаление старой функции требует отдельного продуктового решения.

**Проверенный объём базового среза.** 2 988 путей Git, 33 ID каталога, 171 публичный export, 130 границ пакетов, 31 голосовая команда, 40 инструментов Core и 6 подложек. Из старой матрицы включены 564 сценария (131 + 128 + 98 + 207). Файл и сценарий — разные единицы учёта: один сценарий затрагивает несколько модулей, а общий модуль может обслуживать несколько слоёв. Реестры описывают работы и приёмку, а не итоговые результаты тестов.

## Что сохраняем и что меняем

Сохраняем `GlobeEngine`, общий ECEF/WGS84 и модули `src/geo`, контракт aircraft renderer, lifecycle намерений в менеджере, источники, URL-кодек, реестр рендереров, мировые подписи, Vue/Pinia, стенд с fake engine и старые публичные точки входа. Сохраняем наработки Navara по свету, облакам, stencil и чёткости. Для миграции не нужны Dioxus, новая шина событий, новый сетевой протокол или отдельная копия UI для каждого движка.

Меняем три конкретных зависимости. Каталог из `constructCatalog.js` больше не отбрасывает модель по наличию GPU-фабрики. Инициализация рендера перестаёт очищать данные, как сегодня может происходить в жизненном цикле рейсов. Переключатель управляет подключением сцены, а не владельцем всего приложения. Пока хотя бы один активный компонент не умеет безопасно отсоединиться, новый способ переключения остаётся внутренним экспериментом.

## Владельцы и контракты

| Владелец | Создаётся и прекращает работу | Что хранит |
|---|---|---|
| Сессия приложения | Один раз на страницу; уничтожается при окончательном закрытии | Каталог и менеджер, provenance и права, подписки на источники, часы, история, фильтры, выделение, UI, инструменты, undo/redo там, где он уже есть |
| Модель слоя | При необходимости в сессии; включение и выключение следуют текущим правилам | Нормализованные записи, индекс, ревизия, порядок, окно истории, устаревание, ошибки и координаты. Может работать без GPU/DOM |
| Политика отображения | Общая для двух планет | Отбор по виду, LOD, стиль, подпись, курс, визуальные приоритеты. Получает позу, размер экрана, время и при необходимости результат запроса поверхности |
| Подключение слоя | Отдельно для пары «слой, экземпляр сцены» | GPU-примитивы, материал, индекс попаданий, обработчики ввода. Disposer идемпотентен. Снятие графики не останавливает источник |
| Хост рендерера | Один на экземпляр сцены, возможно временно припаркованный | Canvas, цикл кадра, проекция, камера, глубина, поверхность, видимость, карты, атмосфера, GPU и собственные кредиты |
| Контроллер режима камеры | Сессия; в каждый момент один владелец движения | Карта, follow, кабина, полёт режиссёра и др. Хранит стабильную цель, ENU offset, позу и фазу движения. Новый адаптер получает текущую команду |
| Внешний ресурс | Привязан к своей операции | WebSocket, USB, WebAudio, видео, микрофон, запрос модели или изображений. Данные и медиасеанс могут пережить сцену; текстуры и выбор по глубине принадлежат конкретной сцене |

**Минимальный обмен.** Модель предоставляет снимок с ревизией и изменения после неё (добавление, обновление, удаление). Подписка и чтение снимка образуют согласованную операцию: подписаться с буфером, взять снимок R, применить только события новее R; при разрыве ревизий перечитать снимок из оперативной памяти. Допустима более простая замена целой выборки для малых статических слоёв. Для большого парка нужны переиспользуемые буферы и пакетные изменения; отправлять весь парк в Pinia на кадр нельзя. Модели только публикуют данные, подписчик не может задержать их приём.

**Две независимые оси состояния.** У слоя есть пользовательское намерение и состояние источника (`disabled/loading/live/stale/error`). У каждой сцены отдельно есть состояние представления (`detached/preparing/ready/degraded/unsupported`). Неподдерживаемая графика не превращает ответ на аналитический запрос в пустой список и не сбрасывает пользовательский флажок или share-токен. Отсутствие данных у источника не показывается как поломка планеты. Не начинать платные загрузки или доступ к устройству для вычисления доступности.

**Команды и координаты.** UI, голос, MCP и сценарии вызывают общие команды приложения. Выбор — пара `layerId/objectId`; для составных ключей и смены источника применяются текущие правила слоя. Pick возвращает доменную цель, точку и сведения о поверхности; дриллинг сохраняет порядок и владельца жеста. Бизнес-время задаёт сессия, для интерполяции фиксируется один момент на кадр. На границе явно указываются градусы/радианы, ECEF/геодезические координаты, ENU и эллипсоидальная/ортометрическая высота. Образец terrain/mesh хранит происхождение, качество, время и поколение сцены. Отсутствие глубины, нулевая высота и промах — разные результаты. Для сенсорного ввода, кликов, выделения и мировой подписи использовать единую проекцию и один CSS viewport с учётом DPR.

**Возможности.** Обнаруживать конкретную операцию (например drape на mesh, raster split, depth pick, инстансированные модели, video projection, shader pass). Общая логика решает, возможна ли задача, и предлагает только проверенный режим понижения качества. Выбор Cesium/Navara делается в фабрике графики и в настройке движка. Новая планета реализует контракты операций и прогоняет набор тестов адаптера. Она не получает отдельный каталог, сеть или ветку интерфейса.

## Как менять планету

1. Идентификатор попытки увеличивается для каждого намерения, включая Back/Forward. Сессию не прерывать. Сохранить выбранную цель и режим камеры как данные; URL обновляется как внешнее представление после успешного выбора. Не использовать URL для обмена внутренним состоянием. CPU-модели, фиды и медиасеансы продолжают принимать обновления.
2. Подготовить кандидата невидимым и без ввода. Подключить необходимые операции, актуальную подложку и включённые слои к снимкам с ревизиями. Пока кандидат готовится, команды сессии и обновления позы не теряются. Если AOI управляет запросом, обе сцены используют AOI активного пользователя; подготовительная камера не инициирует второй запрос.
3. Дождаться первого корректного кадра в актуальной позе с видимой подложкой и графикой обязательных видимых слоёв либо согласованной индикацией деградации. Не ждать всех тайлов земли. Есть тайм-аут, отмена и отдельная ветка для скрытой вкладки. Сверить поколение, принять последние ревизии и выбор, атомарно передать ввод, кредиты, проекцию overlay и render-governor кандидату.
4. Снять графические подключения старой сцены, освободить её команды камеры, остановить кадры. Старые callbacks, picks и результаты GPU загрузок проверяют поколение. Держать максимум одну тёплую неактивную сцену только при достаточной памяти. При нехватке памяти или потере контекста освободить и восстановить из моделей. Старый canvas не принимает ввод и не опрашивает провайдеров.
5. При ошибке до передачи ввода освободить кандидата и оставить рабочую сцену. Если старый контекст одновременно потерян, показать восстанавливаемую ошибку, собрать любую разрешённую сцену и подключить к последним ревизиям. При исчезновении цели открыть карту с последней корректной позой, не выбирать случайный соседний объект. Пауза вкладки и выгрузка страницы завершаются независимо от смены движка.

## Очерёдность поставки

Каждая строка — отдельная серия локальных коммитов. Сначала зафиксировать поведение прежнего маршрута, затем получить зелёный результат нового и сравнить. На рабочем preview всё время остаётся используемый исходный путь.

| Этап | Вход | Результат и условие выхода |
|---|---|---|
| 0. Перебазировать план | Текущий чистый коммит, старые W1/W2 и parity | Закрепить ключевые пользовательские маршруты, данные-fixtures, публичные API, загрузку модулей и замеры каждой планеты. Задокументировать расхождения и намеренные различия. Не начинать от более старого main |
| 1. Владельцы сессии | 0 | Отделить destroy приложения от detach графики. Каталог метаданных полный; возможность данных, разрешения и возможность рисовать независимы. Fake/headless без canvas включает слой, опрашивает, выбирает и уничтожает его без утечки |
| 2. Вертикальный пилот | 1 | Flights с детерминированной записью, поданной вместо живого источника через штатный вход. Принять данные без сцены, присоединить Cesium, отсоединить, подключить Navara. Проверить последний снимок, дельты и восстановление; число стартов опроса = 1. Пока только внутренний путь |
| 3. Сопровождение, ввод, кабина | 2 | Один контракт выбора и передачи камеры. Пройти сценарий `71be26`, смену цели/исчезновение, panel reset/restore и вход через C, кнопку и команду. Зафиксировать единое правило входа: выбранного воздушного судна достаточно; режим Contacts добавляет соседей. Это предлагаемое изменение текущей политики Cesium, проверяется отдельно |
| 4. Смена внутри сессии | 2–3 | Реализовать подготовку, commit и rollback из раздела выше. Во внутренней конфигурации переключать только после проверки всех активных подключений; для ещё не перенесённой активной функции дать причину и сохранить работающий вид. Десять переключений, потеря контекста, офлайн и гонки не меняют identity UI/данных и не оставляют второй input/frame/poll |
| 5. Парк, аналитика, вектор | 2–4 | Завершить группы F и V матрицы, включая зависимости Contacts, mixed workloads и повторный вход в слой; закрыть данные, графику обеих реализаций, выбор и деградацию в каждой строке |
| 6. Растры, среда, медиа | 4, поверхности и материал | Группы R и M, basemap/3D, эффекты, ground/mesh, screen-space, радио и SDR. Проверки их времени жизни, атрибуции, сетевой политики и нагрузки. Прогнать Fuji днём, ночью и с орбиты как регрессию предыдущих исправлений |
| 7. Инструменты и хосты | 4–6; модели слоя, которые читает инструмент | Группа T, аннотации, импорт, share/embed, director, voice, agent, MCP, mobile/desktop и shell. Каждая команда доступна по возможности либо возвращает явную причину. Одинаковый ID и эффект от кнопки, голоса, history и восстановленной ссылки |
| 8. Включение штатного маршрута | 0–7 | Полный desktop + mobile + panel набор, бюджеты, доступность, все строки реестров сопоставлены с результатом, нет обязательного слоя без адаптера. Сначала локальная сборка с обратимым выбором реализации. При нарушении порога оставить прежний маршрут; его восстановление не должно менять формат данных |
| 9. Очистка | Штатный путь выдерживает сценарии и повторные возвраты | Удалять по одному старому entrypoint/SDK import только после нуля вызывающих, сохранения публичных контрактов и проверки старых ссылок. Удаление Cesium как поддерживаемого движка в план не входит |

Пилот не блокировать отсутствием полноценного режиссёра в Navara. Общую смену для всех пользователей не объявлять готовой по результатам одного пилота. Если эксперимент не проходит, откатывается коммит переключателя; данные и старые сериализованные ссылки совместимы в обе стороны. Для публичного API с потребителями в других проектах сначала вводится адаптер прежней сигнатуры, затем отдельное удаление с версионированием. Производственные ключи, автоматический push и публикации в план поставки не входят.

## Приёмка и измерения

1. **Без сцены.** Синтетические источники, часы вручную, разрешения и сбои. Повторить init/enable/disable/destroy, отмену до/после первого ответа, пустой ответ, stale, смену viewport и attach с накопившимися дельтами. Сравнивать ID, ревизию, содержимое истории и число подписчиков. Отключённый пользователем слой прекращает работу по прежней политике; отсоединение сцены не создаёт новую сессию.
2. **Одинаковая сцена.** Одни fixtures, timestamp, траектория камеры, карта, DPR и разрешение на Cesium/Navara. Проверять выбор, высотный datum, occlusion, знаки heading/pitch, фильтрацию ночной подсветки, размер модели и z-order, fade/LOD около порога. Сравнивать геометрию/ID с допусками существующих QA, отдельно смотреть реальные скриншоты атмосферы и эффектов. Прозрачный или пустой кадр не считается успехом.
3. **Смена.** В полёте, при открытой форме, во время перетаскивания, при воспроизведении сцены и таймлапса, с работающим радио/микрофоном, при ошибке сети, позднем fetch/GLB, скрытии вкладки, WebGL context loss и Back/Forward. Проверять стабильность объекта сессии, завершение старых операций, единственный потребитель ввода, отсутствие второго опроса, потерянных событий и повторного воспроизведения. У отменённых попыток нет права записывать URL или localStorage.
4. **Нагрузка.** Пустая сцена, 10k гражданских рейсов, военные модели, полигоны со stencil, ветер, полигон+растр+подписи вместе; неподвижная камера, орбита, перелёт и кабина. Фиксировать CPU/GPU frame p50/p95, time-to-first-correct-frame для cold/warm switch, peak memory во время двух сцен и retained ресурсы после 10/50 переключений. Провести не менее трёх чередующихся запусков на одном стенде; отдельно программный GPU CI и реальное железо. Сначала измерить базу заново. Предлагаемый stop-rule — повторяемое ухудшение p95 более чем на 10% против собственной базы движка при том же качестве либо любой устойчивый рост retained объектов/обработчиков. Записывать шум стенда; старые времена из W2 не являются новыми результатами. Для бюджета cold/warm и памяти зафиксировать аппаратные абсолютные пределы в этапе 0 до включения пути.
5. **Поставка.** `npm test`, `npm run check:boundaries`, `npm run build`, `npm run build:panel`, `npm run check:main-chunk`, точечные headless QA и `scripts/qa-engine-switch.mjs`. Для тестовых запусков и сборок выставить пустые `GOOGLE_MAPS_API_KEY` и `CESIUM_ION_TOKEN`, блокировать платные endpoints до навигации (включая серверный прокси). Использовать только назначенный локальный порт и fixtures; не менять настройки приложения по умолчанию. Поддержку платного источника проверять локальными fixtures, живую сеть — лишь при отдельной необходимости и разрешении.

**Финальный тест архитектуры.** Тестовый третий адаптер, реализующий минимально заявленные операции и преднамеренно не поддерживающий одну сложную, подключается через фабрику. Для него не меняются модель рейса, каталог данных, Vue-компонент кабины или схема голосовой команды. На двух поддерживаемых планетах каждая обязательная функция должна пройти реальный рендер-тест. Отказ тестового адаптера полезен для проверки UI деградации, но не заменяет паритет Cesium/Navara.
