# Internationalization (i18n)

God's Eye View ships two locales: **English (`en`)** — the complete baseline
and fallback — and **Simplified Chinese (`zh-CN`)**. There is no framework and
no runtime translation service; the implementation is a small portable engine
plus per-feature message packs.

## Layout

```text
src/i18n/core.js            portable engine (no window/document/localStorage)
src/i18n/index.js           shared instance: t, setLocale, subscribeLocale,
                            formatNumber, formatDateTime, currentLocale
src/i18n/browser.js         entry-only: locale detection + persistence
src/i18n/locales/en.js      aggregates src/i18n/locales/en/<namespace>.js
src/i18n/locales/zh-CN.js   aggregates src/i18n/locales/zh-CN/<namespace>.js
src/ui/staticI18n.js        declarative binding for static markup
src/ui/languageControl.js   the Display-panel language <select>
```

## Rules for new or changed UI text

1. **Never hardcode user-visible English prose.** Import `{ t }` from
   `../i18n/index.js` (path varies by depth) and translate through a key.
2. **English pack values are verbatim.** `en` strings must reproduce the
   previously shipped wording byte-for-byte — source-text regression tests
   assert them. Do not "improve" copy while translating.
3. **Key shape.** Dot paths grouped by feature: `weather.rainRadar`,
   `layers.state.stale`. A key names *meaning*, never the English word.
4. **Interpolation.** Use `{name}` placeholders, never string concatenation:
   `t('welcome.failure.missionOpen', { detail })`. A parameter that is not
   supplied stays visible as `{name}` (and warns in dev) — never `undefined`.
   Plurals are `{ one, other }` objects and require a `count` parameter
   (`t('layers.cleared', { count })`).
5. **Translate at render time.** Never call `t()` at module top level to
   build a constant label map; the map would freeze English. Translate
   inside the render/format function, or store keys and resolve at paint.
6. **Re-render on locale change.** A component holding rendered text
   subscribes with `subscribeLocale(listener)` and repaints its current
   state. Every subscription must be released in the owner's destroy path.
7. **Security is unchanged.** Translated text goes through `textContent` /
   `setAttribute`. Interpolation parameters are never HTML-escaped for you —
   do not place external data (ship names, provider messages) into a string
   that is later assigned via `innerHTML`. Keep dynamic external values in
   their own `textContent` assignments.
8. **Boundaries.** `src/i18n/core.js` and locale packs stay free of browser
   globals so any module may import them. `browser.js` is entry-only.
   Portable package graphs (`layers/*/source|records|ingestion`,
   `sources/*`, `director/*` validation) keep their stable English messages;
   the presentation edge translates known messages (see below).

## Static markup

Templates tag text with `data-i18n="key"` and fixed attributes with
`data-i18n-attr="title:ns.key,aria-label:ns.key2,placeholder:ns.key3"`.
English text stays in the markup as the source of truth; `staticI18n.js`
applies the active locale at boot and reapplies on every switch. Elements
whose text is repainted by feature code must NOT carry `data-i18n` — their
owner translates at render time and re-renders on locale change, so the
binder never clobbers live state.

## Locale selection

Priority: saved choice (`localStorage["gods-eye-view.locale"]`) → browser
preference (`navigator.languages`, then `navigator.language`; any `zh*`
variant selects `zh-CN`) → `en`. A manual choice persists and wins over the
browser. Storage failures (privacy mode) are non-fatal. Switching locales
never reloads the page, never rebuilds the Cesium viewer, and preserves map
view, layer toggles, tracking, panels and form state.

The `index.html` inline bootstrap paints the loading screen in the detected
locale before the app module evaluates; `src/i18n/bootMarkup.test.mjs` fails
if its strings drift from the `zh-CN` pack.

## Formatting

Numbers and dates use the shared `formatNumber` / `formatDateTime` helpers
(cached `Intl` instances keyed by locale). Units and standard symbols
(`°C`, `m/s`, `km/h`, `kt`, `ft`, `dBZ`, UTC) are not translated; UTC times
must keep stating UTC.

## Adding a locale

1. Create `src/i18n/locales/<tag>.js` aggregating per-namespace files under
   `src/i18n/locales/<tag>/`.
2. Add the tag to `SUPPORTED_LOCALES` and `LOCALE_DISPLAY_NAMES` in
   `core.js`, and to the pre-paint bootstrap in `index.html` (with a boot
   string) plus `bootMarkup.test.mjs`.
3. Add `normalizeLocaleTag` handling for the language's variants.
4. Extend `src/i18n/locales/parity.test.mjs` coverage so the new pack is
   checked against `en`.

## Tests

- `src/i18n/core.test.mjs` — engine behavior (fallback, interpolation,
  plurals, formatters, diagnostics).
- `src/i18n/locales/parity.test.mjs` — en/zh key and placeholder parity.
- `src/i18n/bootMarkup.test.mjs` — pre-paint bootstrap drift guard.

Run `npm test`; browser-level acceptance (locale switching, persistence,
layout) is validated per `docs/I18N-COVERAGE.md`.
