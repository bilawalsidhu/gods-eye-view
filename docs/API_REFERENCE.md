# API Reference

Endpoint-level contract for the `/api/*` provider proxies and the new
`server/standalone/headless.mjs` process. Where a consumer's own notes
summarize a field list, **this document is the source of truth** if the two
ever disagree; this is generated by reading (and, for every endpoint below, actually calling) the
provider source.

## Scope

This covers the endpoints a v0 consumer of the headless API needs
(`/healthz`, flights, CCTV, transit) plus enough of their close neighbors to
be usable end to end (track/history sub-routes, the transit feed catalog).
It is **not** a full audit of all ~20 providers in `server/providers/*` — see
[§7](#7-endpoints-not-yet-covered-here) for what's out of scope and why, and
[§8](#8-known-gaps-in-provider-self-documentation) for which provider files
still have no endpoint-level docs of their own at all.

**The complete list of mounts is not here; it is
[`server/apiRoutes.js`](../server/apiRoutes.js)**, the `/api` mount table as
data, which `src/tooling/apiRoutes.test.mjs` checks against what the dev,
preview and headless servers actually install. This document covers a
selected subset of those routes in endpoint-level detail.

Every endpoint here works identically whether served by `vite dev`,
`vite preview`, or `node server/standalone/headless.mjs`: it is the same
middleware in all three cases, and the headless router reproduces Vite's
connect routing exactly (case-insensitive prefixes, with `/` or `.` ending a
mount, so `/api/gbfs.json` reaches the `/api/gbfs` handler). The examples
below were captured from a live `headless.mjs` run.

## Conventions

- All responses are JSON unless noted (CCTV frames are binary images).
- No endpoint requires auth today — every provider assumes a trusted,
  same-origin caller. Auth and TLS are not part of this server yet; nothing
  below should be treated as safe to expose
  publicly as-is.
- `Cache-Control` is set per endpoint and documented per endpoint below; do
  not assume every response is uncacheable. Most proxies cache server-side
  and send `no-store`, but a fresh transit vehicle snapshot is sent as
  `public, max-age=15` (see §4), so an HTTP cache between a client and this
  server may legitimately answer repeat polls for up to 15 seconds.
- An endpoint's own freshness/staleness signaling (headers or body fields) is
  part of its contract — a response can be `200 OK` and _stale_. Treat
  "stale" and "absent" as different facts, not as data quality.

## 1. `GET /healthz` (new — `headless.mjs` only, not present under `vite dev`/`vite preview`)

Liveness/readiness check for the standalone process. No query params.
Only `GET` and `HEAD` of exactly `/healthz` are answered: any other method
gets `405` with `Allow: GET, HEAD`, and a deeper path such as
`/healthz/anything` gets `404`. `HEAD` returns the same status and headers
with no body.

**Response `200`:**

```json
{ "ok": true, "uptimeMs": 1327 }
```

## 2. Flights — OpenSky

### `GET /api/flights?lat=&lon=`

(Named `/api/opensky` before upstream's route rename; the old path is gone.)

Returns a snapshot of aircraft. `lat`/`lon` are optional and do **not** scope
the response — they only supply a fallback anchor point (see below).

**Response body — two possible shapes, same consumer:**

The primary path returns OpenSky's own `/states/all` shape unmodified:

```json
{ "time": 1790570000, "states": [ ["a1b2c3", "UAL123 ", "United States", ...] ] }
```

`states` rows are OpenSky's raw column-array format (documented in OpenSky's
own API docs, not repeated here). **Do not hand-parse these columns** — pass
the whole body to `openSkySnapshot(payload, opts)` /
`normalizeOpenSkyAircraft(row)` from `src/sources/live/aircraft.js`, which
already does this.

When the global snapshot is stale and a `lat`/`lon` anchor was given, the
proxy instead serves a **250 nm regional fallback from adsb.lol**, in a body
shape deliberately normalized to look the same:

```json
{ "time": 1790570000, "states": [ [...] ] }
```

(via `normalizeAdsbLolPointResponse` in `src/data/adsbLolFallback.js`, which
maps adsb.lol's own format into OpenSky-state-vector-compatible rows.)
**The same `openSkySnapshot`/`normalizeOpenSkyAircraft` call handles both
paths uniformly** — that uniformity is the reason to always go through it
rather than branching on which path served the response.

**Which path served the response, and freshness, is in headers, not the body:**

| Header                                                                                        | Meaning                                                           |
| --------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| `X-OpenSky-Cache`                                                                             | `HIT` \| `MISS` \| `STALE` \| `COOLDOWN`                          |
| `X-OpenSky-Auth` / `X-OpenSky-Auth-Mode-Used`                                                 | `oauth` \| `basic` \| `anon` \| `adsblol-regional`                |
| `X-OpenSky-Auth-Mode-Requested`                                                               | From `OPENSKY_AUTH_MODE`                                          |
| `X-OpenSky-Auth-Reason`                                                                       | e.g. `oauth_ok`, `rate_limited_serving_stale`, `forced_anonymous` |
| `X-Feed-Source`                                                                               | `OpenSky Network` (the provider this server uses for the feed)    |
| `X-OpenSky-Stale-Seconds`                                                                     | Present only when serving a stale cache                           |
| `X-OpenSky-Retry-After-Seconds`                                                               | Present only during a rate-limit cooldown                         |
| `X-Flight-Source: adsb.lol` / `X-Flight-Coverage: 250nm regional fallback` / `X-Flight-Count` | Present only on the regional-fallback path                        |

**Status codes:**

- `200` on any served snapshot: fresh, stale, or the adsb.lol regional
  fallback.
- `429` with `{"error":"OpenSky rate limited; proxy cooling down."}` only when
  rate-limited **and** nothing cached **and** no usable fallback anchor.
- Any other non-2xx status from OpenSky is **passed through unchanged** when
  neither the cache nor the regional fallback can serve the request. For
  `401`/`403` the body is an auth-specific `{"error": ...}` message, and
  `X-OpenSky-Auth-Reason` names the cause: `missing_basic_creds`,
  `oauth_invalid_or_missing`, `basic_invalid_credentials`,
  `oauth_invalid_credentials`, `missing_oauth_and_basic_creds`, or
  `auth_required`.
- `502` with `{"error":"OpenSky proxy error"}` (and
  `X-OpenSky-Auth-Reason: proxy_error`) when the proxy itself fails, for
  example on a network error, with nothing cached and no regional fallback.

**Caching:** in-memory, TTL adapts 9s–300s to OpenSky's own remaining rate
budget (`X-Rate-Limit-Remaining`) — see the header block in
`server/providers/aircraft/opensky.js`. Polling faster than the current TTL
returns the same cached body.

**Auth modes** (`OPENSKY_AUTH_MODE` env, default `oauth`): `oauth` (client
credentials), `basic`, `auto` (oauth → basic → anon), `anon` (no
credentials — confirmed functional, rate-limited, in `.env.example`).

### `GET /api/flights/track?icao24=<6-char hex>`

Raw pass-through of OpenSky's `/api/tracks/all` for one aircraft's recent
path. `400` `{"error":"icao24 must be a 6-char hex string"}` on a malformed
id; `502` `{"error":"OpenSky track fetch failed"}` on upstream failure.
Cached per-`icao24`. Feed `payload.path` to `normalizeAircraftTrack` in
`src/sources/live/aircraft.js`.

### `GET /api/military`

Military-flagged aircraft worldwide, raw pass-through of adsb.lol's
`/v2/mil` (`{"ac": [...]}`) — feed to `readsbSnapshot`/`normalizeReadsbAircraft`
in `src/sources/live/aircraft.js`. Headers: `X-Feed-Source: adsb.lol`,
`X-Feed-Cache` (`HIT`/`MISS`/`STALE`), `X-Feed-Age-Ms` (on `HIT`/`STALE`), and
on a cooldown, `X-ADS-B-Upstream-Status` / `X-ADS-B-Retry-After-Seconds`.
In-memory cache, no disk persistence. Formerly `/api/adsblol/mil`.

### `GET /api/military/track?hex=<6-7 char hex>`

One military aircraft's recent trace (formerly `/api/adsblol/trace`). `400`
`{"error":"hex must be a 6-7 char hex string"}` on a malformed id.

`/api/flights` and `/api/military` answer only their own path and hand any
nested path on with `next()`, which is how their `/track` routes, installed
later, are still reached (`exactOnly` in `server/apiRoutes.js`).

## 3. CCTV

Confirmed live (this fork, Austin radius): **2,742 cameras** across all
packs combined; the Austin pack alone (`sourceKind: 'austin-open-data'`) is
always enabled, keyless, pulled from Austin's public open-data portal.

### `GET /api/cctv/sources`

Full catalog, all cities/packs combined — **not scoped by location**, filter
client-side.

**Response `200`:**

```json
{
  "sources": [
    {
      "id": "354",
      "name": "5TH ST / CONGRESS AVE",
      "city": "Austin",
      "cityId": "austin",
      "provider": "Austin Transportation & Public Works",
      "lat": 30.267119,
      "lon": -97.743172,
      "headingDeg": 67.5,
      "headingConfidence": "low",
      "pitchDeg": -18,
      "fovDeg": 44,
      "rangeM": 145,
      "mountHeightM": 8,
      "groundElevationM": 150,
      "feedType": "image",
      "sourceKind": "austin-open-data",
      "poseSource": null,
      "license": "Public city traffic camera frame",
      "credit": "",
      "code": "5TH ST / CONGRESS AVE",
      "groundHeights": {
        "poseHash": "p1-1xmaxab",
        "mountGroundM": 120.78,
        "supports": { "bl": 160.95, "...": "..." }
      }
    }
  ]
}
```

`groundHeights` is Cesium/terrain-calibration data — irrelevant to raw-record collection but harmless to ignore.

### `GET /api/cctv/frame/:id`

One still frame, through a three-tier fallback chain. **Always `200` with an
image body** for a known id (real upstream frame, a Street View still, or a
synthetic placeholder SVG) — never a 404 for a valid camera id. Only a
genuine internal error returns `500 {"error":"CCTV proxy error"}`.

| `X-CCTV-Source` header | Content-Type             | Meaning                                                                               |
| ---------------------- | ------------------------ | ------------------------------------------------------------------------------------- |
| `upstream-image`       | `image/jpeg` (typically) | Real camera frame — the only tier worth keeping for training data.                    |
| `streetview`           | `image/jpeg`             | Google Street View fallback — a static image of the location, not a live observation. |
| `synthetic`            | `image/svg+xml`          | Placeholder graphic — no camera data at all.                                          |

Fetching a frame **also updates that camera's live health entry** as a side
effect (`ok` on `upstream-image`, `degraded` on either fallback) — so
`/api/cctv/health` reflects the _last frame fetch_, not independent upstream
polling.

### `GET /api/cctv/health`

**Response `200`:**

```json
{
  "cameras": [
    {
      "id": "354",
      "status": "ok",
      "sourceKind": "snapshot",
      "label": "Austin Transportation & Public Works",
      "message": "Upstream snapshot active",
      "updatedAt": 1790570000000
    }
  ]
}
```

`status` values observed: `ok`, `degraded` (fallback tier or upstream
failure), `unknown` (never fetched yet in this process's lifetime — health is
in-memory only, reset on restart).

### `GET /api/cctv/stream/:id`

Metadata only — `{"id","feedType","mediaUrl","frameUrl","provider","sourceKind"}`.
`mediaUrl` is non-null only for `feedType: 'video'`.

## 4. Transit — GTFS-Realtime

Confirmed live: `capmetro-austin` returned **230 vehicles** in a single call.

### `GET /api/transit/feeds`

Catalog of the 7 wired-up keyless regions.

**Response `200`** (confirmed live):

```json
{
  "feeds": [
    { "id": "mbta", "region": "Boston, MA", "...": "..." },
    { "id": "capmetro-austin", "region": "Austin, TX", "...": "..." },
    { "id": "metrotransit-msp", "region": "Minneapolis–St Paul, MN" },
    { "id": "hsl-helsinki", "region": "Helsinki, Finland" },
    { "id": "ovapi-nl", "region": "Netherlands" },
    { "id": "entur-norway", "region": "Norway" },
    { "id": "translink-seq", "region": "South East Queensland, Australia" }
  ]
}
```

`Cache-Control: public, max-age=3600` — this list is effectively static.

### `GET /api/transit/vehicles/<feedId>`

`404 {"error":"Unknown transit feed"}` for an unregistered id.

**Response `200`** (confirmed live, `capmetro-austin`):

```json
{
  "feedId": "capmetro-austin",
  "name": "CapMetro",
  "fetchedAt": 1790570100000,
  "feedTimestamp": 1790570086,
  "version": "2.0",
  "entityCount": 230,
  "truncated": false,
  "count": 230,
  "vehicles": [
    {
      "id": "2306",
      "lat": 30.256395,
      "lon": -97.707962,
      "bearing": null,
      "speedMps": 0.158,
      "timestamp": 1790570086,
      "routeId": null,
      "tripId": null,
      "directionId": null,
      "label": "2306",
      "stopId": null,
      "status": null,
      "occupancy": null,
      "timestampSource": "vehicle"
    }
  ]
}
```

Note `timestampSource` (`vehicle` or a repaired/estimated value) — present on
every vehicle from `repairVehicleTimestamps`, in addition to the fields
`normalizeVehicleEntity` itself produces.

**Headers:** `X-GEV-Cache` (`HIT`/`MISS`/`STALE-ERROR`/`NONE`), optional
`X-Transit-Upstream` (source host) and `X-Transit-Contact`, the time the
operator last actually answered, in **epoch milliseconds** (unlike
`feedTimestamp`, which is in seconds). It differs from `fetchedAt` because a
304-revalidated feed keeps its original fetch time. `Cache-Control` is
`public, max-age=15` on a normal response and `no-store` on `STALE-ERROR` and
error responses.

**Failure statuses** (each with a JSON `{"error", "feedId", "retryInSec"}`
body and a `Retry-After` header), when nothing cached can be served:

- `502`: the operator answered badly. Its HTTP status was an error, the
  response was too large, or the feed is differential, which is unsupported
  (that case says so in `error`).
- `504`: any other failure to fetch the feed, such as a timeout or a network
  error.
- `503` (`"Transit feed unavailable"`): the feed is in a retry cooldown after
  a recent failure, so no upstream request was made; retry after
  `retryInSec`. A `503` with `"Transit provider closed"` means the server is
  shutting down.

With a cached snapshot available, any of these failures instead returns the
cached body with `200` and `X-GEV-Cache: STALE-ERROR`.

**Caching:** in-memory, TTL ~ `TRANSIT_PROXY_TTL_MS` (documented in
`src/data/transitProxy.js`); the app's own poll cadence is 15s.

### `GET /api/transit/trail/<feedId>/<vehicleId>`

Only for feeds with `historyRetention: true` (MBTA in the current catalog,
not CapMetro) — `404` for any other feed. Out of scope for v0; documented
here only so its existence isn't a surprise.

## 5. Auth and network exposure (current state)

None of the above requires a token. A bearer-token check, and a reverse
proxy (TLS, CORS, rate limiting) in front of `headless.mjs`, are left for a
later change. Until then, `headless.mjs` enforces three guards of its own:

- **Loopback by default, fail closed otherwise.** It binds to `127.0.0.1`
  unless `GEV_HEADLESS_HOST` says otherwise, and it **refuses to start** on any
  non-loopback address (`0.0.0.0`, `::`, a LAN address, a hostname) unless
  `GEV_HEADLESS_UNSAFE_PUBLIC=1` is also set, logging a warning when it is.
- **Host-header check.** Requests whose `Host` is not an IP literal,
  `localhost`/`*.localhost`, the bind host, or an entry in the
  comma-separated `GEV_ALLOWED_HOSTS` (the same variable and rule the Vite
  servers use, via `build/allowedHosts.js`) are rejected with `403`
  before routing, which blocks DNS-rebinding attacks. Suffix (`.example.com`)
  and wildcard entries are ignored, so each allowed name is listed exactly. A
  container reaching a host-run server as `host.docker.internal` needs that
  name listed.
- **Bounded shutdown.** On `SIGTERM`/`SIGINT`, in-flight responses get
  `GEV_HEADLESS_SHUTDOWN_GRACE_MS` (default 5000) to finish before their
  connections are closed, so a long-lived CCTV stream cannot hold shutdown
  open.

## 6. `headless.mjs`-specific exclusions

`gev-key-setup` (`/api/setup/status`, `/api/setup/keys`) is **not** mounted
under `headless.mjs`. It's documented in `CONTRIBUTING.md` as
development-only, and its POST handler calls a real Vite dev-server
`server.restart()` this process doesn't provide. Everything else
`localProviderPlugins()` returns is mounted unmodified.

## 8. Known gaps in provider self-documentation

`server/providers/traffic.js` (TomTom) is the standard this file holds
itself to: a single header block giving the exact endpoint, upstream URL,
cache/budget behavior, and response shape. Providers with **no**
endpoint-level documentation in their own source today:
`server/providers/military-installations.js`, `server/providers/radio.js`.
Worth fixing at the source (not just here) as a small, separate,
easily-upstreamable contribution.
